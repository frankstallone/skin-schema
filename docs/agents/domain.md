# Domain documentation

Before exploring domain behavior, read root `CONTEXT.md` and the ADRs in `docs/adr/` that concern the work. If absent, proceed without flagging their absence or suggesting their creation upfront.

Use the glossary’s domain terms in issues, proposals, and tests. If a needed concept is missing, check the implementation before proposing a new term.

When a proposal conflicts with an ADR, name the ADR and explain why the decision should be reopened.
